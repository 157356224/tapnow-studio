# TapNow Studio · 本地无限画布工作台

基于 React、TypeScript、React Flow、Vite、Node.js/Express 实现的可交互本地原型。布局参考 TapNow Creative OS 的深色无限画布、媒体节点与工作流。最新版本已按 8 张参考图和录屏调整节点外观及交互。

## 视觉与交互（参考版）

- 全屏黑色点阵背景，四角悬浮操作区，左侧居中工具栏；新画布默认显示中央创建引导。
- 双击画布空白位置弹出「添加到画布」菜单；右键立即关闭；左侧工具条的添加按钮同样可用。
- 图片节点默认竖版，文本节点为方形，视频节点为横版；未选中时仅显示节点类型与素材卡片。
- 鼠标悬停时左右两侧圆形加号渐显，点击自动增添并连线，拖动端口可手动连线；连线为无箭头的贝塞尔曲线。
- 选中节点显示轻量描边、顶部悬浮工具栏、底部提示词与模型参数面板；交互有柔和进场动画。
- 更新画布点阵亮度、透明圆形加号和从节点内向外弹出效果。鼠标靠近节点左右边缘时，加号沿纵向磁吸跟随；连线从节点边框而不是加号中心出发。
- 磁吸区域改为节点左右外侧约 50px；鼠标在节点内部时加号不会追随。跟随响应约 55ms，未选中节点的外侧磁吸同样有效。
- 拉线进入合法目标节点时，节点边框出现雾化扫光：从右侧「+」出发为左→右；从左侧「+」出发为右→左。重复连接、反向回接以及形成循环依赖的目标会变暗模糊，松开不创建连线。
- V5：圆形加号从节点背后弹出；鼠标跟随改为逐帧调度与 GPU translate，移除坐标过渡延迟，独立的内层圆环保留短暂出场动画。
- V5：雾化扫光使用环形蒙版，仅沿节点外缘移动，不再横穿图片或视频画面。
- 将加号拖放到目标节点的卡片内部即可连接，不必瞄准目标加号；文本节点在未进入双击编辑状态时支持从卡片任意位置拖动。
- 旧版项目/素材继续保留。其他 AI 模型仍为演示占位；Seedance 2.0 Fast 另外提供待登录验证的豆包网页浏览器接入，不是官方 API 集成。

## 豆包 Seedance 2.0 Fast：图片参考与真实视频生成接入（V7）

### 登录入口与生成进度修复（本地更新）

1. 点击画布右上角齿轮 → 豆包账号与浏览器。已有账号点旁边的「登录」按钮，程序会打开对应的独立 Chrome；若网页右上角显示「登录」，程序会尝试展开网页登录窗口，扫码/手机号等步骤由用户自行完成。
2. 新增账号现在只需要填写账号备注，Cookie 可留空。点击「创建账号并打开浏览器登录」，浏览器会保存该账号的独立登录会话；Cookie 导入仍可选。
3. 在视频节点选择已登录的账号并点击生成。现在**点击发送就先唤起账号 Chrome**，不会被同一账号的上一条视频任务阻塞而打不开窗口。
4. 如果未登录，视频节点会直接显示明确的「需要登录」错误，而不是一直停在 10%。完成网页登录后，重新点击生成即可。排队任务显示「等待前序任务」，不会伪装成正在生成。
5. 服务重启会将此前中断的任务标记为失败，避免旧项目持久显示「生成中 10%」。真实视频接口仍需结合豆包实际网页控件进行在线验收；网页界面调整可能需要更新自动化选择器。

不需要重新导入其他账号的 Cookie，且**无需重新解压或制作压缩包**，直接使用当前项目目录的 start.bat。若旧版本的独立 Chrome 仍占用该账号 profile，请先正常关闭旧浏览器窗口，再使用画布「登录」打开；不会删除账号资料。

1. 进入右上角齿轮 →「豆包账号与浏览器」，添加账号备注；可选择手动登录，也可导入已有 Cookie。每个账号使用独立的系统 Edge 配置目录。
2. 点击「原生 Edge 登录」，在正常的 Edge 窗口中自行登录豆包。登录后关闭原生窗口，再从画布发送视频任务。
3. 新建视频节点，模型选 Seedance 2.0 Fast，在节点下方选择独立浏览器账号、视频比例和时长。
4. 上传图片到画布中的图片节点，连线指向视频节点，或在提示词中键入 @ 再选择图片节点（例如 @图片1）。视频生成目前只接受图片参考，暂不使用音频/视频参考。
5. 点击生成箭头：后端建立并持久化任务、启动账号独立 Edge，通过豆包网页填写提示词、选模型/比例/时长、上传图片并发送。随后校验实际提交的生成参数（对照 HAR），追踪 SSE 与新视频 ID，尝试下载真实视频并写回项目 JSON 中的原视频节点。

**视频时长滑动条修复：** 豆包当前视频生成网页用 4–15 秒范围滑块设置时长，不能在菜单中寻找“5s”选项。视频节点也改为 4–15 秒滑动条。自动化会先打开网页的“自动 · 10s”设置面板，使用键盘滑块操作或真实指针拖动设置对应秒数，并读取滑块的实际值进行校验；校验失败则停止发送，防止时长错误。

**发送等待与滑块显示值修复：** 选择 5s 后还会核对豆包时长弹窗实际显示的秒数（如不能接受显示 9s）。只有滑块内部值和面板显示值均与节点一致才继续发送；不一致会先尝试重新校准，仍不一致则显示明确错误并停止提交。豆包输入框现在等待发送按钮完成异步启用；提交和下载请求的事件监听都具备错误与超时清理，不会因 Playwright 的未处理超时导致整个本地 API 进程退出。修复直接写入当前项目，不需要重新下载 ZIP。

### 豆包人机验证图片加载失败（5202）网络排查

**原生浏览器人工登录：** 在“设置 → 豆包账号与浏览器”中点击“原生 Edge 登录”。该窗口由 Windows 正常启动，不由 Playwright 控制。系统 Edge 账号目录使用独立的 ID-edge 路径，旧便携 Chrome 的历史目录和加密 Cookie 文件保留但不再使用。**人工登录完成后正常关闭原生 Edge 窗口**，再从画布视频节点发送；不允许两个进程同时占用同一账号的 Edge 配置。若 Edge 首次使用新的账号目录，需要重新登录。

**浏览器安全：** 所有自动化账号使用系统 Edge，并启用 Chromium 沙箱。原生人工登录窗口不使用 Playwright 的自动化启动参数。旧版捆绑的便携 Chrome 程序已从项目移除。

**项目不再提供账号代理设置和代理切换接口。** 账号由本机系统 Edge 正常联网。验证码出现 [5202] 时，可以在浏览器里点击刷新并人工操作；本项目不会跳过或自动执行验证。

“检测资源错误”显示浏览器中捕获的图片、脚本或接口资源失败的域名、HTTP 状态及网络错误码；不读取验证答案、图片内容、Cookie、Authorization 或完整请求 URL。若检测中没有对应失败事件，但验证码弹窗仍报 5202，则可能是验证服务在响应正文中返回的错误，不能仅凭浏览器网络信息断定原因。

已实现账号列表、Windows DPAPI Cookie 加密、独立 Edge profile、图片节点 @ 引用、任务队列、基于 HAR 的发送字段核对、SSE 事件解析、视频 ID 识别、实际视频容器校验及服务器侧项目持久化。**尚未实测豆包登录后的真实模型选项与发送/下载控件，所以不能保证首个真实视频任务自动完成。** 当前要求以豆包页面显示的 Seedance 2.0 Fast 为准；HAR 中观察到的内部标识 seedance_v2.0 并不能证明它只代表 Fast 版本。

自动化适配器始终让豆包网页生成动态会话参数并执行上传/发送，不会将 HAR 中的登录状态、Cookie、msToken、a_bogus 或其他时效性参数硬编码到接口中。页面结构变化时任务返回 needs-attention，而不生成假的视频结果。

账号设置中的“接口记录”用于记录对应浏览器账号发出的豆包 XHR / Fetch 请求的域名、路径、方法和状态码（只保留最多 250 条）。不会记录请求参数、Cookie、授权头、请求/响应正文或媒体地址；未核实网页登录及实际生成之前，不应把此记录视为已接通豆包的非公开接口。

Cookie 保存在 server/data/doubao-secrets 下的 DPAPI 密文，账号浏览器配置在 server/data/doubao-profiles 下，均不包含在导出的 ZIP 中。请勿向任何人分享登录 Cookie；更换 Windows 登录用户后需要重新导入。只有用户主动发送豆包生成任务时，对应提示词与引用图片才会传往豆包。

接口：GET/POST /api/doubao/accounts，POST /api/doubao/accounts/:id/open，GET /api/doubao/accounts/:id/trace，DELETE /api/doubao/accounts/:id，POST /api/doubao/jobs，GET /api/doubao/jobs/:id。

## Windows 一键启动

双击 start.bat。首次运行会安装 npm 依赖。**需要本机已安装 Microsoft Edge**，项目不再附带便携 Chrome，也无需另行安装 Playwright Chromium。

**V9 启动稳定性修复：** 启动脚本会先检查 3701 API / 5173 画布端口；已有本项目服务时直接复用，不再使用 concurrently -k 重复启动导致整个进程组被终止。若端口被其他程序占用，则输出明确错误。Vite 文件监听排除 server/data（包含 Edge 的 Default/Sessions）、server/uploads、work、dist，避免 Windows 文件锁报 EBUSY。重复双击启动不会结束已运行的服务。

所有账号统一使用本机 Microsoft Edge。Edge 资料目录为 server/data/doubao-profiles/<账号ID>-edge；早期账号的旧 Chrome 资料目录 server/data/doubao-profiles/<账号ID> 会保留，避免丢失用户数据，但不再用来启动浏览器。

手动启动（PowerShell）：

    cd "C:\Users\lhw20\Documents\Codex\2026-10-31\tapnow-3\outputs\tapnow-studio"
    npm install
    npm run dev

## 当前可用功能

1. 无限画布：鼠标滚轮平移、中键/右键拖拽、双指缩放、节点自由移动、拖动连线、选框多选。
2. 四类节点：文本（内嵌编辑）、图片、视频、音频。支持上传和预览本地素材。
3. 快捷创建：左侧工具栏、双击画布、把文件拖到画布、从节点右侧的 + 衍生下游节点。
4. 编辑参数：提示词、模型名称、画幅比例、分辨率、视频时长和节点旁路（bypass）。
5. 工作流：后端进行拓扑排序、循环依赖检测和跳过节点；右上角模拟运行全部。
6. 模拟生成：显示进度，在源节点右侧产生一个新结果节点和连线。这是演示占位结果，不是 AI 生成的照片或视频。
7. 项目：多个画布、自动保存、本地 JSON 数据库、JSON 导入导出和三套初始模板。
8. 交互：多选、复制/粘贴、撤销/重做、删除、快速缩放与画布适配。
9. Agent 面板：输入创意、选择结果类型、引用选中节点，自动搭建工作流节点（未接 LLM）。

## 数据保存位置

- 项目 JSON：server/data/projects.json
- 已上传的图片、视频、音频：server/uploads/
- Muse 独立 Edge 登录资料：server/data/muse-profiles/（按账号隔离）
- Muse 账号/任务索引：server/data/muse-accounts.json、server/data/muse-jobs.json

普通画布编辑仅保存到本地。用户主动通过豆包账号执行真实生成时，对应的提示词与参考图片会上传给豆包。初始示例使用公开 Unsplash 图片链接，仅用于视觉演示；要进行豆包图片参考生成，需要将图片上传到本地素材库。

## Muse 图片与视频生成

1. 选择图片或视频节点，将生成方式切换为 **Muse**（图片节点默认 Muse，视频节点可在“豆包生成/Muse 生成”间切换）。
2. 打开 Muse 账号管理，创建账号备注。点击登录打开该账号专属的 Microsoft Edge，亲自登录 https://muse.ai/，完成登录后关闭该浏览器窗口。
3. 回到画布选择对应 Muse 账号，输入自然语言提示词并选择比例。Muse 视频仅提供 4–10 秒。将参考图片节点连接到图片/视频生成节点，**再在输入框里插入 @图片1、@图片2 等需要的图片**；连接而未 @ 引用的图片不会被上传。Muse 不需要模型选择。
4. 点击节点发送时，后端自动打开该 Muse Edge 账号资料，**先点击“旁聊”右侧 + 新建会话，再上传仅被 @ 引用的图片，最后发送包含“生成视频/图片”、比例、时长和参考图关系的文字提示词**。若找不到加号或上传预览，则终止本次提交，不复用旧会话。
5. 任务状态持续更新，找到生成媒体后下载到本地 server/uploads/ 并回填原节点。每个 Muse 账号的任务按顺序执行，避免混用不同会话结果。

### Muse 多账号额度与自动分配

- 左侧画布工具栏新增“查看 Muse 额度”（仪表图标），鼠标悬停显示所有账号的剩余、已用额度及合计；每个账号按 100% 计算，总容量为账号数 × 100%，同步失败的账号显示“未知”，不虚报剩余。
- 前台与后台每 60 秒刷新额度。额度来自登录状态下的 Muse Next.js Server Action（POST 根路径），仅复用各账号独立 Edge 的浏览器会话，不提取 Cookie 或 Token。
- 图片、视频节点 Muse 账号下拉框默认选“自动选择”。服务端优先使用剩余额度最多且空闲的账号，明确耗尽的账号不会被选择；接口暂不可读时会显示未校验并轮换未知额度账号作为兜底，保证原有生成流程仍能尝试。
- Muse 浏览器加载后先等待至少 3 秒，再确认输入框是否出现；未加载完成时继续等待，避免立即误判“未登录”。
- 如果 Muse 更新 Next.js Action，可用环境变量 MUSE_QUOTA_ACTION_ID 覆盖其 Action ID；如接口参数改变，可用 MUSE_QUOTA_ACTION_ARGS 配置 JSON 参数数组。提供的抓包只有请求标头，未包含完整 27 字节请求正文，因此真实账号的实时额度查询仍需要以实际响应验证。

Muse 支持纯文字以及连接图片节点后按 @ 引用进行参考生图/生视频。只接受已上传本地素材库的 PNG/JPG/WebP 文件，未引用的已连接图片不会发送。用户自己登录，不导入或重放 HAR 中的 Cookie、令牌。Muse 并未提供在本项目中验证过的公开生成 API，使用 Playwright 驱动其登录网页；**首次使用图片引用需要在实际登录后确认附件预览和上传状态、发送按钮及结果下载的页面结构**，网站更新可能导致选择器需要适配。自动化模拟测试通过不代表已经进行真实站点的扣费生成验收。

## 现阶段边界

- 豆包视频支持 Seedance 2.0 Mini / Fast；图片与视频节点可通过 Muse 独立浏览器发送真实任务。其他未接入的生成节点仍使用演示结果。右上角“运行工作流”目前仍是演示运行，不会自动发送真实 Muse/豆包任务。
- Seedance 浏览器接入依赖实际已登录的豆包账号及可用生成额度；网页控件选择和真实生成结果下载尚待端到端验收，不属于公开稳定 API。
- Agent 面板目前只将用户输入转换为画布节点，没有真实对话智能体。
- 未实现 TapNow 的高阶图片局部重绘、视频剪辑与重打光、3D 预演、实时多人协作、账户系统。
- 当前为高还原设计与核心业务原型，不代表 TapNow 官方代码或逐像素完整复刻。

## GitHub 私有仓库与启动增量更新

Windows 首次使用需要安装 Node.js 22.12+（推荐 24 LTS）、Git 和 Microsoft Edge。
从自己的 GitHub 私有仓库克隆项目后，直接双击 `start.bat`：

1. 启动前运行 `scripts/bootstrap.mjs`，使用 Git 检查 `origin` 当前分支是否有新提交。只快进同步远程发生变化的源码文件，未变化的文件不重新检出。
2. 对比 `package-lock.json` 的 SHA-256 和当前机器的 Node 主版本；首次启动或依赖变化时自动运行 `npm ci` 下载依赖，其余启动复用现有 `node_modules`。
3. 更新失败、离线或本地存在未提交的已跟踪改动时，不覆盖用户本地源码；依赖安装失败会恢复旧依赖并尝试回滚更新。
4. 本地 `server/data/`（Muse/豆包浏览器资料、账号、登录状态、项目）与 `server/uploads/`（生成媒体）始终在 `.gitignore` 中，不上传、不被 Git 更新覆盖。

可运行 `npm run update` 单独检查更新与依赖，或在启动前设置 `TAPNOW_SKIP_UPDATE=1` 仅跳过 Git 网络更新。私有仓库的自动检查需要本机 Git Credential Manager 已授权 GitHub；不要把 PAT 写入源码、远程 URL 或 Git 配置。

检查更新行为可运行 `npm run test:updater`，该测试使用操作系统临时目录中的本地 Git 仓库，不修改真实仓库或账号资料。
